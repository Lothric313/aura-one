# Растяжение Aura One в сцене «Всё внутри»

Гарнитура начинает растягиваться вдоль одной оси уже во время перехода из «Ваш мир. Ваш цвет» в левую колонку. Подлёт и раскрытие используют единый прогресс без ожидания до или после движения. Крупнее показанная модель остаётся слева, характеристики — справа. Все детали сохраняют X/Y и ориентацию, расходятся и сходятся только по Z. При переходе к контроллерам устройство собирается.

## Подключение и файлы

Анимация уже подключена к существующей сцене характеристик и единому прогрессу Lenis/ScrollTrigger. Отдельная секция HTML, второй timeline или RAF не нужны.

- src/partsConfig.js: единый EXPLODE_CONFIG. mount: front_shell фиксирует камеру на передней панели; для неё layer не применяется. split.distance задаёт растяжение, spring.turns — витки, parts[].layer — конечный слой детали внутри зазора. X/Y берутся из исходной модели; origin используется для отсутствующих деталей.
- src/explodeScene.js: привязки GLB, дополнительные детали, общий коэффициент растяжения, сгруппированные винты и прямой рендер.
- src/springCable.js: одна TubeGeometry на пружину; шаг витков изменяется через существующие position/normal buffers.
- src/scene.js и src/framing.js: композиция слева от информации; на мобильных — над текстом. Границы кадрирования следуют текущему растяжению и плавно сужаются к левой колонке, поэтому модель не уменьшается заранее под полный объём раскрытия.
- src/motion.js, src/timeline.js, src/config.js: одинаковая длительность переходов; раскрытие и сборка используют общий ритм прокрутки.
- src/background.js: чёрный фон эпизода. src/main.js и src/headset.js: плавный скролл и освобождение ресурсов.
- scripts/check-explode.mjs, подключённый к npm run check: только осевое движение, отсутствие отскоков и вращений, обратимость, скрытие деталей, мобильный бюджет, кадрирование, буферы и dispose.

Прямые переходы: /#specifications и /#explode. Границы в EXPLODE_CONFIG.chapter: .345–.55 — единое движение и раскрытие; .55–.585 — сборка; с .59 — контроллеры. Раскрытие сразу переходит в сборку при дальнейшем скролле. Положение приближено по Z на .22; объём для кадрирования задаётся в EXPLODE_CONFIG.framing. Обе фазы занимают по 160.98vh скролла и используют одну кривую smoothstep. Обратное движение точно повторяет прямое. Вся история — 1870.83vh, с одним линейным временем прокрутки и одинаковой длительностью всех 11 переходов; отдельных замедлений после контроллеров нет. Lenis остаётся единственным слоем сглаживания, а навигация и интерфейс используют MOTION.duration = .75 с.

## Детали и замена из Blender

Используется исходный public/models/aura-one.glb. front_shell и back_shell собираются из существующих мешей корпуса, лицевой накладки и ремней. lens_left, lens_right, sensors_11, sensors_12 взяты из GLB вместе с их носителями и возвращаются в точные исходные положения перед сценой погружения.

Камеры sensors_11 / sensors_12 вместе со стеклянными крышками sensors_3 / sensors_4 и соседними элементами жёстко закреплены на front_shell. Их положение относительно передней панели одинаково при любом прогрессе; отдельного разлёта камер нет. Исходные материалы камер сохраняются.

33 внутренних элемента на desktop: 17 основных узлов и 16 винтов. Внутри процедурных узлов дополнительно видны микросхемы, дорожки, 12 рёбер радиатора и семь лопастей вентилятора. Недостающие объекты отмечены userData.todo и userData.proceduralPlaceholder:

| Имена | Процедурные TODO |
| --- | --- |
| pcb_main, pcb_radio, pcb_power | три платы с микросхемами и дорожками |
| battery | аккумулятор с контактами |
| display_left, display_right | круглые оптические модули с тёмной подложкой |
| frame_inner | компактный контурный каркас с вырезом под переносицу |
| heatsink | радиатор с 12 рёбрами |
| fan | вентилятор |
| shield_left, shield_right | круглые экранирующие пластины |
| cable_left, cable_right | соединительные кабели |
| screws_1 … screws_16 | винты, сгруппированные в один InstancedMesh |

Экспортируйте замену с точным именем внутри headsetGroup, в собранной позиции и исходном масштабе. Найденный узел автоматически заменяет соответствующую заглушку; найденный винт исключается из общего батча. Сохраните корни controller_left и controller_right. Диагностика: window.aura.productState.explode и data-product-state.

Процедурные платы, аккумулятор, радиатор, вентилятор, кабели и винты уменьшены до внутреннего объёма корпуса. Проверка проходит по вершинам геометрии, включая микросхемы и рёбра в InstancedMesh: их поперечный контур должен помещаться внутри заданного профиля в EXPLODE_CONFIG.internals. Оригинальные круглые линзы GLB не заменяются. Материалы плат — тёмный зелёный с медными дорожками, подложек и каркаса — тёмный пластик, экранов — приглушённый металл; свечение ослаблено.

## Производительность

Дополнительные детали видны после раздвижения корпуса на 22% полного хода (internals.revealAt), до этого скрыты, и снова скрываются при смыкании. За пределами эпизода их трансформации не пересчитываются. 16 винтов используют один draw call; микросхемы на каждой плате, рёбра радиатора и лопасти также используют InstancedMesh. Геометрия и материалы создаются один раз, освобождаются через dispose; instance buffers обновляются только при изменении растяжения.

На узком экране или при снижении качества: девять основных деталей, восемь винтов и две пружины с меньшим числом сегментов. Bloom, глубина резкости и дополнительные render targets отключены. Используется общий renderer и существующее адаптивное качество. npm run check и npm run build проверяют и собирают проект; в Windows с защищённым кэшем можно использовать npm run build -- --configLoader runner.
